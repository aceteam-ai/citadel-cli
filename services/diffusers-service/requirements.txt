# Full text-encoder tokenizer stack (citadel-cli#829). AutoTokenizer /
# AutoPipelineForText2Image silently depend on different optional backends
# per model family, and a missing one fails at model-LOAD time (mid-provision,
# on the node), not at image-build time. sentencepiece + protobuf back the T5
# tokenizer used by SD 3.5 Medium and (planned) LTX-Video; ftfy is
# CLIPTokenizer's optional text-cleaning backend (used by the default
# SDXL-Turbo). Real incident: LTX-Video's T5 tokenizer failed twice in a row
# on a live node -- first `ModuleNotFoundError: No module named 'tiktoken'`
# (this transformers version's tokenizer-loading path imported it on that
# model's tokenizer even though tiktoken's own BPE format isn't otherwise
# involved -- root cause not fully traced beyond the observed error; treat as
# an empirical requirement for this pin set, not a documented mechanism), then
# `ValueError: Error parsing tokenizer/spiece.model` once tiktoken alone was
# hand-installed but sentencepiece/protobuf were not (reproduced locally:
# services/diffusers-service/scripts/check_tokenizer_deps.py fails the same
# way against Lightricks/LTX-Video's tokenizer with sentencepiece
# uninstalled). Bake all four so no supported model can hit this class of
# failure again. Pinned to versions contemporaneous with the
# transformers/diffusers pins above; do NOT loosen any pin in this file when
# adding to it.
